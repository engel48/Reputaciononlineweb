0 · Antes que nada: dejar el servidor arriba (Coolify)

Hoy producción está caída en bucle de reinicio porque falta la variable JWT_SECRET. Hasta arreglar esto no se puede probar nada (ni login, ni redes).

En Coolify → tu app → pestaña Environment Variables, asegurá estas (y luego Redeploy):

NEXTAUTH_URL=https://reputaciononline.com.co JWT_SECRET=<secreto largo y aleatorio> # obligatoria: sin esto la app no arranca NEXTAUTH_SECRET=<secreto largo y aleatorio> ENCRYPTION_SECRET=<secreto largo y aleatorio> # cifra los tokens de las redes
Para generar un secreto fuerte: en una terminal con Node corré node -e "console.log(require('crypto').randomBytes(48).toString('hex'))" y pegá el resultado.
Ojo: NEXTAUTH_URL debe ser exactamente https://reputaciononline.com.co (con .co, sin barra final). Ese valor define todas las URLs de callback que registres abajo. Si lo cambiás, hay que volver a registrar los callbacks.

1 · URLs de callback que vas a registrar

Cada consola te pide una "URL de redirección / callback autorizada". Son estas exactas (copialas tal cual; deben coincidir carácter por carácter):

https://reputaciononline.com.co/api/auth/youtube/callback https://reputaciononline.com.co/api/auth/facebook/callback https://reputaciononline.com.co/api/auth/instagram/callback https://reputaciononline.com.co/api/auth/twitter/callback

Para probar también en tu PC (opcional), agregá además las mismas con http://localhost:3000 en lugar del dominio.

2 · Google / YouTube

Consola: console.cloud.google.com/apis/credentials

Pasos

  1. Entrá al proyecto de Google Cloud (o creá uno: "Reputación Online").
  2. Habilitá la YouTube Data API v3: activar aquí.
  3. En Credenciales → tu "OAuth 2.0 Client ID" de tipo Web application → en Authorized redirect URIs agregá:
    https://reputaciononline.com.co/api/auth/youtube/callback
  4. En OAuth consent screen (pantalla de consentimiento): configurar aquí → tipo External, completá nombre de la app, logo, dominio, email de soporte y enlaces de privacidad/términos.
  5. Pasá la app de Testing a In production y enviá a verificación.
Verificación de Google (scope sensible): el scope que usamos es https://www.googleapis.com/auth/youtube.readonly, clasificado como sensible. Buena noticia los scopes sensibles requieren revisión de Google (verificación de marca ~2–3 días + justificación del scope, puede tardar días), pero NO exigen la costosa auditoría anual de seguridad de terceros (eso es solo para scopes "restringidos" tipo Gmail/Drive).
Mientras esperás la verificación podés probar agregando hasta 100 usuarios en "Test users": esas cuentas ya pueden conectar YouTube aunque la app diga "no verificada".

Variables en Coolify (ya las tenés cargadas, verificá)

GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... NEXT_PUBLIC_GOOGLE_CLIENT_ID=... # mismo valor que GOOGLE_CLIENT_ID YOUTUBE_API_KEY=...

3 · Meta — Facebook + Instagram

Consola: developers.facebook.com/apps · Instagram reutiliza la misma app de Facebook (no creás credenciales aparte).

Pasos

  1. Abrí tu app (o creá una de tipo Business).
  2. Agregá el producto Facebook Login → Settings → Valid OAuth Redirect URIs:
    https://reputaciononline.com.co/api/auth/facebook/callback https://reputaciononline.com.co/api/auth/instagram/callback
  3. Pasá la app a modo Live (interruptor arriba, al lado del nombre de la app).
  4. Completá la Verificación de Negocio (Business Verification) en Meta Business Suite.
  5. Enviá a App Review los permisos que usamos (Advanced Access): pages_show_list, pages_read_engagement, instagram_basic, instagram_manage_insights. (email y public_profile ya vienen por defecto.)
Este es el trámite más lento. Meta exige App Review + Verificación de Negocio para que cualquier usuario (que no seas vos) pueda conectar su cuenta. Sin la review aprobada, solo las cuentas con rol en la app pueden conectar (modo desarrollo).
Instagram (importante): la "Instagram Basic Display API" fue discontinuada. Hoy se accede vía Instagram API con Facebook Login: el usuario debe tener una cuenta de Instagram Business o Creator vinculada a una página de Facebook. Una cuenta personal de Instagram no se puede conectar.

Variables en Coolify (ya cargadas, verificá)

NEXT_PUBLIC_FACEBOOK_APP_ID=... # App ID de la app de Meta FACEBOOK_APP_SECRET=... # App Secret NEXT_PUBLIC_INSTAGRAM_CLIENT_ID=... # mismo App ID de Facebook

4 · X (Twitter) — requiere acción: credenciales faltan

Consola: developer.x.com/en/portal/dashboard

Pasos

  1. Creá un Project y dentro una App.
  2. En la app → User authentication settings → Set up / Edit:
    • App permissions: Read
    • Type of App: Web App, Automated App or Bot (confidential client)
    • Callback URI / Redirect URL:
      https://reputaciononline.com.co/api/auth/twitter/callback
    • Website URL: https://reputaciononline.com.co
  3. Guardá. X te muestra el OAuth 2.0 Client ID y Client Secret (el secret se ve una sola vez: copialo ahí mismo).
  4. Verificá que en "Keys and Tokens" tengas el OAuth 2.0 Client ID y Secret.

Variables en Coolify — cargar estas (hoy están vacías)

NEXT_PUBLIC_TWITTER_CLIENT_ID=... # el OAuth 2.0 Client ID TWITTER_CLIENT_ID=... # mismo Client ID TWITTER_CLIENT_SECRET=... # el Client Secret
Los scopes que pedimos son tweet.read users.read follows.read offline.access y usamos PKCE. El tier gratuito de X permite el login OAuth igual; lo que está muy limitado son las lecturas posteriores de la API (cantidad de tweets/menciones por mes).

5 · Cómo probar (después de configurar y redeploy)

A · Que el inicio del OAuth responde

En el navegador (logueado en la plataforma), abrí estas URLs: deben redirigir a la pantalla de permiso de cada red (no dar 404 ni "config_missing"):

https://reputaciononline.com.co/api/auth/youtube?redirect=/oauth-app-success https://reputaciononline.com.co/api/auth/facebook?redirect=/oauth-app-success https://reputaciononline.com.co/api/auth/instagram?redirect=/oauth-app-success https://reputaciononline.com.co/api/auth/twitter?redirect=/oauth-app-success

B · Conectar desde la web

  1. Entrá a Dashboard → Redes sociales y tocá Conectar en cada red.
  2. Autorizá en la ventana de la red. Debe volver y mostrar la cuenta como conectada.

C · Conectar desde la app móvil

  1. En la app, andá a Más → Redes sociales y tocá Conectar.
  2. Se abre el WebView con el permiso; al autorizar, el WebView se cierra solo y la tarjeta queda "conectada".

D · Verificar en el panel admin

En el portal web → /admin/redes deberías ver la cuenta recién conectada, con su estado de token (válido/vencido). Ahí también podés desconectar o forzar refresh.

Si algo falla, el motivo viaja en la URL de retorno como ?error=... (ej. redirect_uri_mismatch = el callback no coincide exactamente con el registrado en la consola; config_missing = falta la variable de entorno de esa red).
