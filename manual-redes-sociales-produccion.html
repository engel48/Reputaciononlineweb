Manual de configuración · Verificado online (junio 2026)

Reputación Online · Redes sociales en producción

Qué tenés que hacer vos (consolas de desarrollador + Coolify) para que las 4 redes queden conectando en producción. El código ya está corregido y desplegado.

📍 Qué se arregló (por qué antes solo funcionaba YouTube)

Antes, Facebook/Instagram/X iniciaban el login en el navegador, leyendo unas variables (NEXT_PUBLIC_*) que Next.js "hornea" al compilar. En el servidor de producción esas variables no estaban en la compilación, así que quedaban vacías y esas 3 redes fallaban con "no está configurado". YouTube funcionaba porque iniciaba en el servidor.

Ahora las 4 redes inician en el servidor y leen las credenciales en tiempo de ejecución. Resultado: alcanza con cargar las credenciales como variables de entorno en Coolify (runtime) y Redeploy. Ya no hace falta tocar el build ni pasar NEXT_PUBLIC_* de forma especial.

0 · Servidor arriba (Coolify)

En Coolify → tu app → Environment Variables, asegurá estas y luego Redeploy:

NEXTAUTH_URL=https://reputaciononline.com.co JWT_SECRET=<secreto largo y aleatorio> # obligatoria: sin esto la app no arranca NEXTAUTH_SECRET=<secreto largo y aleatorio> ENCRYPTION_SECRET=<secreto largo y aleatorio> # cifra los tokens de las redes
Para generar un secreto fuerte, en una terminal con Node: node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
Ojo: NEXTAUTH_URL debe ser exactamente https://reputaciononline.com.co (con .co, sin barra final). Ese valor define todas las URLs de callback de abajo.

1 · URLs de callback que vas a registrar

Cada consola pide una "URL de redirección / callback autorizada". Son estas exactas (deben coincidir carácter por carácter):

https://reputaciononline.com.co/api/auth/youtube/callback https://reputaciononline.com.co/api/auth/facebook/callback https://reputaciononline.com.co/api/auth/instagram/callback https://reputaciononline.com.co/api/auth/twitter/callback

Para probar también en tu PC (opcional), agregá además las mismas con http://localhost:3000 en lugar del dominio.

2 · Google / YouTube

Consola: console.cloud.google.com/apis/credentials

  1. Entrá al proyecto de Google Cloud (o creá uno).
  2. Habilitá la YouTube Data API v3: activar aquí.
  3. En Credenciales → tu "OAuth 2.0 Client ID" tipo Web application → en Authorized redirect URIs agregá:
    https://reputaciononline.com.co/api/auth/youtube/callback
  4. En OAuth consent screen (configurar): tipo External, completá nombre, logo, dominio, email de soporte y privacidad/términos.
  5. Pasá la app de Testing a In production y enviá a verificación.
Verificación de Google: el scope youtube.readonly es sensible. Requiere revisión de Google (verificación de marca ~2–3 días + justificación del scope), pero NO exige la costosa auditoría anual de seguridad de terceros (eso es solo para scopes "restringidos" tipo Gmail/Drive).
Mientras esperás, agregá hasta 100 cuentas en "Test users": ya pueden conectar aunque la app figure "no verificada".

Variables en Coolify (runtime)

GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... NEXT_PUBLIC_GOOGLE_CLIENT_ID=... # mismo valor que GOOGLE_CLIENT_ID YOUTUBE_API_KEY=...

3 · Meta — Facebook + Instagram

Consola: developers.facebook.com/apps · Instagram reutiliza la misma app de Facebook.

  1. Abrí tu app (o creá una tipo Business).
  2. Agregá Facebook Login → Settings → Valid OAuth Redirect URIs:
    https://reputaciononline.com.co/api/auth/facebook/callback https://reputaciononline.com.co/api/auth/instagram/callback
  3. Pasá la app a modo Live (interruptor arriba).
  4. Completá la Verificación de Negocio en Meta Business Suite.
  5. Enviá a App Review los permisos que usamos (Advanced Access): pages_show_list, pages_read_engagement, instagram_basic, instagram_manage_insights.
Este es el trámite más lento. Meta exige App Review + Verificación de Negocio para que cualquier usuario (que no seas vos) pueda conectar. Sin la review, solo las cuentas con rol en la app pueden conectar (modo desarrollo).
Instagram: la "Instagram Basic Display API" fue discontinuada. Hoy se accede vía Instagram con Facebook Login: el usuario debe tener una cuenta de Instagram Business o Creator vinculada a una página de Facebook. Una cuenta personal no se puede conectar.

Variables en Coolify (runtime)

NEXT_PUBLIC_FACEBOOK_APP_ID=... # App ID de la app de Meta FACEBOOK_APP_SECRET=... # App Secret NEXT_PUBLIC_INSTAGRAM_CLIENT_ID=... # mismo App ID de Facebook
Scopes (permisos) configurables: una app de Meta nueva solo trae public_profile aprobado, así que por defecto la conexión pide solo eso (alcanza para vincular la cuenta). Después de aprobar el App Review, activá los datos de página/Instagram seteando en Coolify (sin tocar código):
FACEBOOK_SCOPES=email,public_profile,pages_read_engagement,pages_show_list INSTAGRAM_SCOPES=email,public_profile,pages_read_engagement,pages_show_list,instagram_basic,instagram_manage_insights
Si pedís un permiso que aún no está aprobado, Facebook bloquea con "Invalid Scopes".

4 · X (Twitter) — acción requerida: faltan credenciales

Consola: developer.x.com/en/portal/dashboard

  1. Creá un Project y dentro una App.
  2. En la app → User authentication settings → Set up / Edit:
    • App permissions: Read
    • Type of App: Web App, Automated App or Bot (confidential client)
    • Callback URI / Redirect URL:
      https://reputaciononline.com.co/api/auth/twitter/callback
    • Website URL: https://reputaciononline.com.co
  3. Guardá. X muestra el OAuth 2.0 Client ID y Client Secret (el secret se ve una sola vez: copialo ahí mismo).

Variables en Coolify — cargar estas (hoy están vacías)

NEXT_PUBLIC_TWITTER_CLIENT_ID=... # el OAuth 2.0 Client ID TWITTER_CLIENT_ID=... # mismo Client ID TWITTER_CLIENT_SECRET=... # el Client Secret
Usamos scopes tweet.read users.read follows.read offline.access con PKCE. El tier gratuito de X permite el login OAuth; lo limitado son las lecturas posteriores de la API.

5 · Cómo probar (después de configurar y Redeploy)

A · Que el inicio del OAuth responde

En el navegador (logueado en la plataforma), abrí estas URLs: deben redirigir a la pantalla de permiso de cada red (no dar 404 ni "config_missing"):

https://reputaciononline.com.co/api/auth/youtube?redirect=/dashboard/redes-sociales https://reputaciononline.com.co/api/auth/facebook?redirect=/dashboard/redes-sociales https://reputaciononline.com.co/api/auth/instagram?redirect=/dashboard/redes-sociales https://reputaciononline.com.co/api/auth/twitter?redirect=/dashboard/redes-sociales

B · Conectar desde la web

  1. Entrá a Dashboard → Redes sociales y tocá Conectar en cada red.
  2. Autorizá en la ventana de la red. Debe volver y mostrar la cuenta como conectada.

C · Conectar desde la app móvil

  1. En la app: Más → Redes sociales → Conectar.
  2. Se abre el permiso en un WebView; al autorizar, se cierra solo y la tarjeta queda "conectada".

D · Verificar en el panel admin

En el portal web → /admin/redes deberías ver la cuenta conectada, con su estado de token (válido/vencido), y podés desconectar o forzar refresh.

Si algo falla, el motivo viaja en la URL de retorno como ?error=... (ej. redirect_uri_mismatch = el callback no coincide con el registrado en la consola; config_missing = falta la variable de entorno de esa red en Coolify).
